# Margin v0.5.1 Integrity Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.5.1 with the completed updater hardening plus conservative fixes for case-variant rename collisions, encoded image cleanup, concurrent link repair, and release artifact integrity.

**Architecture:** Keep each fix at its existing boundary: path identity in `paths.rs`, Markdown asset liveness in `assets.rs`, multi-file transaction validation in `notes.rs`, and distribution integrity in release scripts/workflows. Preserve the plain-file model and fail conservatively whenever filesystem or Markdown identity is ambiguous.

**Tech Stack:** Rust 2021, Tauri 2, React 18, TypeScript, Vitest, Node.js release scripts, PowerShell, Bash, GitHub Actions, pnpm 10.15.1.

**Spec:** `docs/superpowers/specs/2026-08-17-v0.5.1-integrity-hardening-design.md`

## Global Constraints

- Notes remain portable UTF-8 Markdown files with optional YAML front matter.
- No database or repository-local note storage is introduced.
- Ambiguity is resolved in favor of preserving user data.
- Existing Windows, Apple Silicon macOS, and x64 Linux targets remain supported.
- In-app updater artifacts continue to use the configured Tauri signing key.
- v0.5.1 does not claim Apple Developer ID notarization or Windows Authenticode signing.
- Use `cmd.exe` and pnpm for every repository command.
- Write each behavior test first and observe the expected failure before editing production code.

```rust
    let library = temporary_library();
    fs::create_dir_all(&library).unwrap();
    let source = library.join("Foo.md");
    let distinct = library.join("foo.md");
    fs::write(&source, "source").unwrap();
    fs::write(&distinct, "distinct").unwrap();

    assert_eq!(fs::read_to_string(&distinct).unwrap(), "distinct");
    fs::remove_dir_all(&library).ok();
}
```
